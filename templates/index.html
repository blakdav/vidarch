vidarch

Paste video links and download them to the archive volume. Takes plain page URLs, lines with a filename attached, or a raw manifest dump from the browser network panel.

Building a link list

The goal of this section is to produce lines in the format the box below expects, one per video:

-o "01 - First Video.%(ext)s" https://player.host.example/video/12345
-o "02 - Second Video.%(ext)s" https://player.host.example/video/12346

Bare URLs work too, but then filenames come from the video host, which often stores internal production names rather than the titles shown on the page. The -o prefix sets the name you want, and the numeric prefix fixes the order, since files sort by name and not by the order they finish downloading.

Producing that list by hand is impractical past a handful of videos. The route below extracts it from the site's own data instead. It covers sites that load their content as JSON, which is most of them; other routes will be added here as they come up.

1. Find the content JSON

  1. Open a page that plays one of the videos and press F12.
  2. Go to the Network panel, tick Preserve log, and reload the page.
  3. Click the Fetch/XHR filter. Look for a response of a few kilobytes or more whose name resembles the page you are on. Skip anything served by analytics or advertising hosts.
  4. Click a candidate and open the Preview tab to browse it as a tree. The right one contains the page's own content — titles you recognise from the screen.

2. Check it has both halves

A usable response holds an identifier for the video — a field named something like vimeo_id, videoId, youtube_id, or an embed URL pointing at a video host — and a human title near it, such as title, pageTitle, or display_name.

Often the response also lists every item in the collection, while holding the video identifier only for the item currently open. That is still enough: the list supplies the route for each item, and one request per item collects the rest.

3. Copy two things

Right-click the row and take Copy → Copy response for the body, then Copy → Copy URL for the address. Both matter. The body shows which fields hold the identifier and title; the URL shows the route pattern for requesting the same data for other items.

4. Ask an assistant for a script

The script has to match the site's own field names and route pattern, so it cannot be a fixed recipe. Paste the response body and the request URL into an assistant along with the whole block below. The constraints are what separate a script that works from one that looks right and produces nothing.

Here is a JSON response from a site, and the URL it came from.
Write a browser console script that collects every video in the
collection and prints one line per video in exactly this format:

-o "01 - Title.%(ext)s" https://player.host.example/video/12345

Reading the data:
- Do not hardcode values that change between deploys or between
  items: build ids, tokens, session values, or path segments that
  vary. Read those from the page's own loaded state, which
  framework apps usually expose on a global object.
- Do hardcode facts about the site that do not change, such as
  the video host's domain. Work those out yourself from the
  sample and write them into the script as literals.
- Verify every object path against the sample I pasted before
  using it. Do not assume a field sits at the top level.
- Do not hardcode any path segment that also appears as a field
  in the data. Read it from the data instead, or parse it out of
  the item's own path field. Segments that look fixed in this one
  sample often vary elsewhere in the same collection.
- The sample is one page's data. If it lists every item in the
  collection but carries the video identifier only for the item
  currently loaded, the script must fetch each remaining item's
  data individually and read the identifier from each response.
  A script that reads only the already-loaded state will find one
  video and warn on all the rest, which is wrong.

Building request URLs:
- Fetch same-origin so my session cookie is sent automatically.
- Use location.origin for requests back to this site, never for
  the player URL. The video host is a separate domain.
- Identify that video host now, from the field names and embed
  URLs in the sample I pasted, and write it into the script as a
  literal string. Do not detect it at runtime by scanning iframes
  or network entries: the player is often not loaded when the
  script runs, and the script will stop before producing
  anything.
- Do not concatenate path fields directly into a URL template.
  Strip leading and trailing slashes from each piece first, then
  join with single slashes. Missing and doubled separators are
  the most common way this fails.

Verify before looping:
- Before processing the collection, run one request for a single
  item. Log the URL you constructed. If the response is not 200,
  or yields no video identifier, print that URL and stop.
- Do not let the loop run over every item producing the same
  failure repeatedly. One clear error beats seventy identical
  ones.

Output:
- Number the lines so files sort in the site's own order.
- Use the title shown to a reader on the page, not the video
  host's internal name.
- Strip only characters that are actually illegal in filenames:
  / \ : * ? " < > |
  Keep ampersands, parentheses, commas, apostrophes and dashes.
- Put a short delay between requests.
- Print with console.log, not copy(), which is unavailable inside
  an async function.
- Warn and skip any item with no video identifier rather than
  emitting a broken line.
- Print a final count of lines produced versus items examined.
- Give me the script as a downloadable .txt file rather than in
  the chat. Plain JavaScript only, no markdown code fences and no
  commentary in the file, so it pastes straight into the console
  without the formatting being mangled in transit.

If it still fails, paste the console output back and ask for a fix. The verification step above means the first error message should name the URL that failed, which is usually enough to identify the problem.

5. Run it and paste the output

Run the script in the Console tab, on a page from that collection, while logged in. Same-origin requests carry your session automatically, so no credentials are entered or stored anywhere.

Select the printed block, copy it, and paste it into the links box. Check the line count against what the site says the collection holds, then use Check links to confirm the filenames look right before starting.

Referer

Some video hosts serve content only when the request claims to come from the site that embeds it. If downloads fail with a permission or embed error, put the URL of a page containing the player into the referer field. One value usually covers every video on the same site.

When there is no useful JSON

If the page builds video URLs in a way that cannot be reproduced outside the browser, filter the Network panel on m3u8 — or use the Media type tab if the text filter comes up empty — play through each video, then right-click a row and choose Copy all listed URLs. The whole dump can be pasted as-is.

Treat this as a last resort. Those links carry no title, so filenames come out generic, and they are signed with roughly an hour of life, so capture and download have to happen in one sitting.
